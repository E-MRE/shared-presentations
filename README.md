# Vektör

A Turkish team presentation library built with React, Vite and modular Firebase Auth/Firestore. Members upload HTML bundles or PPTX files; administrators review submissions. HTML runs inside an opaque sandbox, and PPTX is downloaded without conversion. Firestore holds metadata and bounded binary chunks; Firebase Storage is not used.

Use Node 24 LTS (or Node 22.12+) and `npm ci` with the committed lockfile. This run uses Node 24 and Java 21. `npm run dev` starts local development against the real `shared-presentations` Firebase project by default. Copy `.env.example` to `.env.local` and set `VITE_USE_EMULATORS=true` only when deliberately testing local emulators. Localhost does not silently select emulators. Start them with `npx firebase emulators:start --project shared-presentations --only auth,firestore`.

The refreshed UI follows the approved attached prototype. See [latest UI, deployment and secret-scan record](docs/UI-SON-DUZELTMELER-2026-10-06.md), [design decisions](docs/TASARIM-KARARLARI.md), [prioritized plan](docs/DUZELTME-PLANI.md), [external dependencies](docs/KULLANICI-BAGIMLILIKLARI.md) and [delivery instructions](docs/TESLIM-VE-CALISTIRMA.md).

`npm run build` emits the production app in `dist`; `npm run preview -- --host 0.0.0.0 --port 4175 --strictPort` previews it on localhost and the local network; port 4173 is reserved for E2E. The preview was stopped at the user's request after acceptance. `npm run lint` and `node scripts/check-release.mjs` are local gates. The checker is read-only: it performs no deploy, push or network mutation.

Automated composition browser tests use explicit deterministic dependency injection, real feature components and the real content pipeline. Production `main.tsx` always selects real Firebase dependencies. Test fixtures are never selected from a production query string or global login switch. `npm run test:e2e -- --workers=1` runs Chromium with a single worker. See [acceptance](docs/ACCEPTANCE.md) for the exact scope and manual limitations and [operations](docs/OPERATIONS.md) for project-pinned emulator and release commands.

The app Chromium suite is split from the Node auth-boundary suite: `npm run test:e2e -- --workers=1` discovers the browser scenarios in `tests/e2e/*.pw.ts`; `npx vitest run tests/e2e/auth-boundary.test.ts --maxWorkers=1` runs the seven preserved Node tests. Build before Chromium (`npm run build`), because production smoke and prepaint checks serve the actual `dist` output on a separate ephemeral localhost preview. All browser tests block non-local transport before navigation. The suite includes 80 viewport captures at 375/1280 × 900, light/dark, DPR 1, plus keyboard/fullscreen, theme/storage and measured overflow checks. Captures document rendered states; they are not pixel-baseline comparisons or live backend acceptance. Exact command results and external-verification limits are in the acceptance record.
