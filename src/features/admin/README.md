# Admin feature

Exports: `AdminPage`, `PendingBadge`, `usePendingCount`, `createFirestoreAdminAdapter` and their typed props/options. L09 supplies stable `PresentationDataService`, frozen `AuthState`, and a stable `AdminReadAdapter`. Construct the production adapter with an explicit `getAuthState` getter reading the latest committed authentication state, plus optional Firestore db. Update that getter before any consumer may initiate an action. Tests inject deterministic adapters only; production never substitutes fake auth/data.

AdminPage renders pending oldest first and a separately paginated all-status list newest updated first. All review/delete operations use the frozen data service. Reject requires a trimmed nonempty note up to 1000 characters (matching firestore.rules), unpublish/delete require the shared confirmation Modal, and pending operations disable duplicate submission. Errors retain entered notes and recoverable dialogs. Successful actions refresh both lists; the independent pending snapshot updates the live count. Session keys include UID, role, data service and adapter; layout cleanup discards late reads/mutations and disposes listeners during auth/role/dependency changes.

The production adapter guards both operations and callbacks with the current member/admin getter. All-status pagination uses updatedAt descending and document ID descending, fetches one extra document, and preserves timestamp seconds/nanoseconds in the typed cursor's string sortValue. Pending subscription queries the entire pending set without a page limit and registers with the shared listener lifecycle. Permission errors dispose it; hook retry opens a fresh subscription. Queries never read chunks. Contract tests mock the actual Firebase module transport and exercise exact cursor values and listener registry cleanup without live Firebase.

For the shared Header, use `const pending = usePendingCount(auth, adapter)` and pass `pending.count ?? undefined` to `Header.pendingCount` / `AppLayout.pendingCount`. Render `pending.error` and a retry button calling `pending.retry` in the surrounding layout. Set `AdminPage.showPendingBadge={false}` when Header already announces this count. The optional standalone PendingBadge announces one atomic contextual phrase and exposes retry; mount one count live region in a composition. Hooks dispose on unmount: mount the subscriber in the intended route/layout lifetime and recreate it when a route-wide listener cleanup occurs. Keep adapter identity stable across unrelated renders.

Focused ui-ux-pro-max mapping: contextual count guidance -> atomic PendingBadge status and typed Header hookup; keyboard focus/required error guidance -> shared Modal, invalid note focus and inline described errors; async effects cleanup -> session layout invalidation, subscription cleanup and generation-protected refresh. Chromium assertions cover those decisions, long content, both themes and 375/1280 screenshots.
