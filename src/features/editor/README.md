# Upload and owner edit integration

Import `UploadPage`, `EditPage`, or controlled `PresentationEditor` from this directory. All require the current frozen `AuthState` and a stable `EditorService` (`Pick<PresentationDataService, 'getDeck' | 'getAllChunks' | 'createDeck' | 'updateDeck'>`). Use the real data-service singleton or an application-owned stable instance. The production defaults call `preparePresentation`, `processCoverOverride`, `reconstructPresentation`, and `generateDefaultCover` from the frozen content API. Optional `content` function overrides support deterministic error and race tests; the application does not need overrides.

L09 should place `ThemeProvider` and `ToastProvider` around the router/layout, load the foundation styles once, and render `<UploadPage auth={auth} service={service}/>` at `/yeni` and `<EditPage auth={auth} service={service}/>` at `/duzenle/:id`, inside the shared `AppLayout`. The editor root is a section: AppLayout owns the only main landmark. Route adapters default cancel/back to `/benim` and successful completion to `/s/${encodeURIComponent(deck.id)}` with history replacement. Optional `onClose` and `onComplete(deck)` callbacks override these destinations. The controlled editor supports `mode="create"` or `mode="edit" id={id}` without router hooks. Without a completion callback it retains a success state and disables further writes; without a close callback its cancel controls have no application navigation effect, so integrations should supply one.

Identity, admin role, route ID, service identity, and every content function identity key the session. Keep dependencies stable for the lifetime of a route. Dependency changes intentionally discard unsaved form/preview state in that commit. Layout cleanup invalidates late reads/preparation/cover/preview/mutations. Sent operations cannot be recalled; stale completion cannot navigate, refresh another session, or write again. A synchronous lock covers every async editor operation and save before React paints.

Only authenticated members process files or call the service. Edit metadata ownership is checked for every user including administrators before exposing the form. Original HTML chunks load only on explicit preview, after manifest/version/size/count bounds. Preview opens the shared native Modal, locks background scroll, restores trigger focus and uses an opaque srcdoc iframe with exactly `sandbox="allow-scripts"` and separate `allow="fullscreen"`. The temporary capture helper is owned by the existing content pipeline; stored/prepared bytes are reconstructed without adding editor helpers. PPTX shows file information and an antivirus warning, without a converter or iframe.

Folder relative paths are preserved into the frozen pipeline, with existing normalization/common-root/HTML-entry logic. Multiple HTML candidates require an explicit entry selection, including when index.html exists. ZIP extraction uses the existing content API. Failed attempted replacements block saving until resolved or the user explicitly chooses “Mevcut içeriği koru”. Metadata-only updates omit replacementContent and cover; cover reset is an explicit default-generation choice, while original-cover restore omits cover. Content replacement deliberately chooses its new pipeline cover unless the user has selected an uploaded override. No status/counter/owner/review fields are written by the editor; create/update own pending transition and atomics in the data service.

Field checks use shared validators/constants, plus a full HTTPS URL parser rejecting credentials. Complete payload validators run before injected or real service calls. Progress reports actual read/preparation/cover/preview/save phases, with an indeterminate progress element; there is no artificial percentage. Raw fields and selected input survive recoverable errors. Cover object URLs are component-owned and revoked on replacement/unmount; preview uses srcdoc and needs no frame URL.

The cover picker separates image upload/drop from ready covers with keyboard-accessible tabs. Preparation diagnostics remain in the pipeline result; the UI suppresses normalization/capture details and summarizes only possible rendering problems or internet dependencies. Transient operation outcomes use keyed global notifications; field validation and contextual retry controls remain in the form. Save success is announced before route navigation.
